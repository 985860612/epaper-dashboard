# 逐点连续回放失败与回退

2026-11-08，用户要求股票回放每次只新增一个点，等待本次渲染完成后立即渲染下一个点。本轮以独立研究工作树 epaper-stock-replay 中的三处运行源码实现：app.h、screen.cpp、epaper_dashboard.ino；字体、227字节波形、电压、行情解析和分区未修改。完整242点回放未通过，用户反馈“屏幕花屏了”。本版本不得作为已验证固件使用。

实验版本为 epaper-dashboard-0.1.9-point-replay，应用1288577字节、静态RAM91392字节，应用SHA256为6f965b27e2f16664609b19f9978fbbbedf4ac185b7be62df055a21aea524721d。编译、交易规则测试、直接提取生产回放函数的0–245点边界与单步递增检查、上传校验通过。上述软件检查不代表屏幕持续局刷通过。

使用设备抓取的长江电力2026-11-06历史快照，共242点。初始不显示点；每次成功等待BUSY结束并同步旧帧RAM后，才将可见点数加一。移除原来的3秒间隔，回放期间暂停天气/行情HTTPS抓取与股票轮播，Header固定，窗口仍为0,40,400,260。页面明确标注历史回放。

首刷20763ms。串口记录的前8次局刷均约1023ms，观察端完成间隔1.073–1.082秒，Header哈希均为9e055cda；第8次后关闭串口。独立HTTP观察显示成功局刷计数继续增长至65，第66次尝试在约58ms后被判为异常，随后停止回放并自动全刷恢复。58ms明显偏短，不能把状态码unsupported_or_timeout直接解释为8秒超时。故障时完整串口记录不可得；通信、BUSY、电源或持续驱动状态的具体根因待确认，不将重复上电或连续刷新频率视为已证实原因。

用户反馈花屏后，通过USB发送partial_stop，收到WATCH_STOPPED；随后烧回已完成12步测试的epaper-dashboard-0.1.9-stock-replay，上传Hash校验通过。回退应用SHA256为984d56aa96b0c9d5966013ee6277714be0c714d2bc2c311aaf709fe1b95c376d。设备API确认版本已回退，全刷1次、耗时20765ms、局刷0次、rendering=false、displayError为空、状态history_replay_ready；当前保持静止，不自动开始回放。画面是否物理恢复仍待用户确认，软件状态不代替实际观感。

本轮未清除NVS、未改变默认4MB分区、未保存演示配置。主项目运行源码与稳定发布仍为0.1.8，失败实验源码及二进制单独保留；没有提交或推送。重新设计连续逐点驱动前，须保留本次故障记录，确认恢复画面，增加长时间运行验证；不能仅凭前8次成功判断全轮可用。

source.zip和experimental-firmware.zip为失败候选，rollback-upload.log及rollback-status.json为回退证据。serial.log只覆盖前8次，observation.json为之后的API观测，failure-status.json记录自动恢复全刷后的状态；它们没有提供每一帧的完整硬件波形。SHA256SUMS用于核验本目录文件。

后续用户明确反馈“已经恢复正常了”，并要求再次触发刷新。此反馈确认回退后的实际画面恢复；重新触发沿用12步分段版，不恢复失败的连续逐点版。
