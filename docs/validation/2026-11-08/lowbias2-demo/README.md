# 第二低偏置候选的初始化异常与基线恢复

第二候选`epaper-dashboard-0.1.9-lowbias2`试图在黑白会话保持08h偏置、全刷前还原原值，并在每次局刷入口读状态和重新初始化SPI。应用1286241字节，编译与上传校验通过，分区不变。源码、未验证固件和日志保留，不作为可用发布。

启动后全刷BUSY持续高超过90秒，计数full=0、partial=0，显示错误为全刷BUSY未就绪。尚未执行局刷分支，不能证明该候选可运行，也不能把启动故障直接归因于偏置调整。自动长暂停复测被取消，串口观察器已关闭。

随后通过上传校验恢复用户已确认可局刷的0.1.9-lut227，应用SHA256为7d7d137769c80b6f69a1c0c93157a0b4d73713700ccf4eebd51b2de9aa091774。首次报告全刷353ms，与正常约20秒明显不符，当时未宣称画面恢复成功。要求用户将ESP32与墨水屏驱动板一起断电5秒再上电；用户回复已重新上电。

重新上电后全刷20765ms完成，full=1、partial=0、displayError为空；随后6次窗口请求932–935ms完成，full仍为1、partial=6。第二次请求后关闭串口，其余请求独立继续，最终rendering=false。当前设备保留0.1.9-lut227有限次数演示，时分固定，每6轮暂停；NVS原显示设置与凭据不变。

本目录恢复证据区分固件上传成功、正常全刷完成与局刷请求完成。用户之前已确认原基线能局刷，本次重新上电后的背景颜色仍待观察，不能将低偏置颜色优化标记为完成。SHA256SUMS用于核验。
