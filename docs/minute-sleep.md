# 每分钟唤醒与 BOOT 配置窗口

2026-11-09，用户选择省电优先、每分钟唤醒更新、网页按需开启，并确认板上有BOOT按钮。

本版使用手动Light-sleep，保留RAM中的前帧、已加载波形和绘图状态；不使用会重启应用并丢失前帧的Deep-sleep。进入前停止网页与Wi-Fi，保持屏幕SPI／复位引脚状态，醒来释放保持并恢复联网，不重新初始化屏幕。发生休眠配置或执行异常时记录powerError，保持配置窗口，不反复自动重试。

## 使用方式

- 上电或复位后提供90秒临时配置窗口；启动与首次全刷也占用此时间。
- 短按GPIO0的BOOT按钮，开启10分钟配置窗口。睡眠中通过GPIO低电平唤醒；运行或刷新时也检测按钮。
- 网页有“保持配置10分钟”和“立即省电”。保存设置或打开已认证的网页也延长配置窗口；单纯读取状态不会延长，避免后台轮询导致永不休眠。
- 配置窗口期间不睡眠，电流仍接近日常工作电流；窗口结束后才进入每分钟唤醒循环。
- 休眠期间网页离线。本次Mac会话中USB串口日志在轻睡眠后未恢复，改用认证API和计数核验；短按BOOT用于网页配置，不保证恢复USB日志。下次USB烧录建议按RESET进入启动窗口；正常下载模式仍可使用BOOT加RESET进入，不修改分区或擦除NVS。

## 调度

60秒行情配置按墙上时钟的分钟边界取样。休眠到下一分钟，必要时为天气、卡片／股票轮换和维护全刷的更早截止时间提前醒来。不是每次重连都抓天气或重启SNTP；天气保留30分钟调度，阿里云保留小时校准。刷新跨过分钟时，再完成新一分钟的取样及时间更新才休眠，防止20秒全刷后漏掉一分钟。

原配置、固定卡片、自动交易时段股票优先及每10分钟股票维护全刷保持。主动断网不会被当作新的页面布局来重画；新一轮联网后再绘制。无Wi-Fi配置／连接失败进入原有设置热点时保持唤醒，以便修复网络。

## 构建

新增睡眠代码后普通编译超出现有应用分区，因此仅对C++与链接启用LTO。SDK的C文件保持原编译方式，避免其弱回溯钩子在LTO下产生跨地址区链接错误。字模、波形数据逐字节保留，没有缩小字库或修改原分区。

使用`uv run tools/build_firmware.py`，可通过`--build-path`指定构建目录。构建器传入`compiler.cpp.extra_flags=-flto`及`compiler.c.elf.extra_flags=-flto`，上传仍用Arduino CLI upload --verify复用产物。仅把-flto写入所有C文件会触发现有SDK的链接错误，不要修改全局Arduino平台文件。

编译实测1289837字节，原上限1310720字节；静态RAM88928字节。分钟、微秒边界、计时器回绕、配置到期及跨分钟刷新检查通过；字模和波形完全未变。实机结果、BOOT物理操作与用户电流读数分别记录，不根据软件sleep标志推算mA。

## 功耗口径与恢复

用户原报告USB／5V整机约50mA；0.4.5降频后反馈约40mA。当前版实际睡眠电流和包含联网／刷新的整分钟平均电流需分别读表。配置窗口的40mA不能当作休眠电流；开发板及驱动板自身的稳压器、USB和指示灯也会影响整机读数。

0.4.5原分区恢复固件独立保留，可在BOOT配置窗口上传回退；Wi-Fi、和风Key、股票及密码不进入新源码或日志。
